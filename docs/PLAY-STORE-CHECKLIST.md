# 🏪 چک‌لیست انتشار در گوگل‌پلی

این سند برای زمانی است که بخواهیم اپ اندروید را در Google Play منتشر کنیم.
همه‌چیز حول یک نکته می‌چرخد: **گوگل مجوزهای پیامک را فقط برای فهرست بسته‌ای
از کاربردها می‌پذیرد.**

---

## ⚖️ مبنای قانونی ما

طبق [سیاست رسمی گوگل](https://support.google.com/googleplay/android-developer/answer/10208820)،
یکی از کاربردهای مجاز این است:

> **SMS-based financial transactions** — «مثلاً UPI، تأیید تراکنش‌های مالی»
> مجوزهای مجاز: `READ_SMS`، `RECEIVE_SMS`، `SEND_SMS`

CubePay دقیقاً همین است: پیامک واریز بانکی را می‌خواند تا یک تراکنش مالی را
تأیید کند. این استثنا هر سه مجوز مورد نیاز ما را پوشش می‌دهد.

**آنچه ممنوع است** فورواردر عمومی است — اپی که هر پیامکی را به هر مقصدی که
کاربر بخواهد بفرستد. تفاوت در همان «هر مقصدی» است.

---

## 🔐 چرا اپ ما فورواردر عمومی نیست

سه دلیل که باید در فرم اظهار مجوز نوشته شوند:

1. **مقصد قابل انتخاب نیست.** در بیلد گوگل‌پلی (`play` flavor) فیلد آدرس
   وب‌هوک قفل است و فقط از تنظیمات حساب فروشنده پر می‌شود. سرور هم مستقل
   از اپ، `allowed_webhooks` را اعمال می‌کند.
2. **فقط پیامک واریز.** فیلترها با چیپ‌های بانک‌های ایرانی و کلمه‌های کلیدی
   واریز ساخته می‌شوند.
3. **بدون حساب فروشندگی کار نمی‌کند.** اپ برای کاربر عادی کاربردی ندارد.

## 📢 متن Prominent disclosure

گوگل الزام کرده این متن **قبل** از درخواست مجوز پیامک، در خود اپ و به شکل
یک صفحه یا دیالوگ جدا نشان داده شود — نه در سیاست حریم خصوصی، نه در دیالوگ
خود اندروید. کاربر باید بتواند رد کند.

### عنوان

```
چرا CubePay به پیامک‌های شما نیاز دارد
```

### متن

```
برای اینکه پرداخت مشتری‌هاتون خودکار تأیید بشه، CubePay باید پیامک واریز
بانک رو ببینه.

این یعنی:

• فقط پیامک‌هایی که با فیلتر خودتون می‌خورن (بانک و کلمه‌ی واریز) خونده
  می‌شن — بقیه‌ی پیامک‌ها اصلاً بررسی نمی‌شن.

• متن همون پیامک‌ها، شماره‌ی فرستنده و زمانش برای سرور CubePay فرستاده
  می‌شه تا سفارش مشتری تأیید بشه. مقصد ثابته و قابل تغییر نیست.

• دفترچه تلفن، تماس‌ها، موقعیت مکانی و فایل‌هاتون خونده نمی‌شن.

• هر وقت بخواید می‌تونید فیلترها رو خاموش کنید یا مجوز رو از تنظیمات
  گوشی پس بگیرید.

جزئیات کامل در سیاست حریم خصوصی.
```

### دکمه‌ها

```
[ متوجه شدم، ادامه ]      [ الان نه ]      [ سیاست حریم خصوصی ]
```

اگر کاربر «الان نه» را بزند، مجوزی درخواست نمی‌شود و اپ بدون فوروارد پیامک
کار می‌کند (فقط وب‌هوک دستی و اعلان‌ها).

## 🧾 پاسخ‌های فرم Data Safety

| پرسش | پاسخ |
|---|---|
| SMS جمع‌آوری می‌شود؟ | بله — متن پیامک‌های مطابق فیلتر |
| هدف | عملکرد اصلی اپ (تأیید تراکنش مالی) |
| اختیاری است؟ | بله، کاربر می‌تواند رد کند |
| رمزگذاری در انتقال؟ | بله (HTTPS + امضای HMAC-SHA256) |
| قابل حذف؟ | بله، با درخواست حذف حساب |
| با شخص ثالث به اشتراک گذاشته می‌شود؟ | خیر |
| شناسه‌ی دستگاه | بله — `ANDROID_ID`، برای تفکیک گوشی‌های یک فروشنده |
| Crash log | محلی؛ فقط با اقدام دستی کاربر ارسال می‌شود |

## ⚠️ نکته‌های حساب توسعه‌دهنده

- حساب **شخصی** ساخته‌شده بعد از نوامبر ۲۰۲۳: قبل از انتشار باید ۱۲ تستر
  به‌مدت ۱۴ روز پیوسته در تست بسته بمانند.
  ([منبع](https://support.google.com/googleplay/android-developer/answer/14151465))
- حساب **سازمانی** این شرط را ندارد، ولی شماره‌ی D-U-N-S می‌خواهد.
- `applicationId` بعد از اولین آپلود **هیچ‌وقت** قابل تغییر نیست:
  `ir.cubepay.app`
