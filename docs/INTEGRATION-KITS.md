# 📦 بسته‌های اتصال PHP، Python و Node.js

برای اتصال سایت یا ربات اختصاصی به **درگاه کارت‌به‌کارت عادی CubePay**. اگر برنامه‌نویس ندارید، این صفحه را به سازندهٔ فروشگاهتان بدهید؛ برای وردپرس از [افزونهٔ وردپرس](../integrations/wordpress-plugin-guide.md) استفاده کنید.

**[دانلود همهٔ بسته‌ها در یک ZIP](https://github.com/cubepy/cubepay-doc/raw/refs/heads/main/downloads/CubePay-integration-kits.zip)** · [فایل‌های قابل بررسی](../integrations/kits/README.md)

## 🚀 چهار قدم اتصال

1. توکن API حساب فروشنده را از ربات بردارید و فقط در تنظیمات محرمانهٔ سرور نگه دارید.
2. بستهٔ زبان برنامه را انتخاب کنید و مسیر یک دیتابیس خصوصی و ماندگار را تنظیم کنید.
3. با شمارهٔ یکتای سفارش و مبلغ به **ریال** فاکتور بسازید؛ مشتری را به `payment_link` دریافتی بفرستید.
4. مسیر callback را به Store وصل کنید و پردازشگر تحویل سفارش را به `delivery_outbox` متصل کنید؛ ابتدا با حساب آزمایشی بررسی کنید.

| زبان | پیش‌نیاز | راهنمای اجرا |
|---|---|---|
| PHP | 8.1+، cURL، PDO SQLite | [شروع PHP](../integrations/kits/php/README.md) |
| Python | 3.10+، کتابخانه‌های استاندارد | [شروع Python](../integrations/kits/python/README.md) |
| Node.js | 22.13+، node:sqlite | [شروع Node.js](../integrations/kits/node/README.md) |

## ✅ بسته‌ها چه کاری انجام می‌دهند؟

- ساخت فاکتور و استعلام نتیجه با توکن فروشنده، با ذخیرهٔ سفارش و شناسهٔ پرداخت.
- کنترل شمارهٔ سفارش و مبلغ پاسخ در برابر دادهٔ ذخیره‌شدهٔ فروشگاه.
- ثبت یک ردیف تحویل برای هر سفارش تأییدشده و مدیریت callback تکراری.
- حفظ سفارش نامعلوم برای بررسی، به‌جای ساخت دوباره یا تحویل بدون تأیید.

بسته خودش محصول تحویل نمی‌دهد و کیف پول فروشگاه را شارژ نمی‌کند. برای API تحویل خارجی، مقصد باید `authority` را به‌عنوان کلید یکتای عملیات بپذیرد؛ صرف داشتن outbox، تحویل خارجی را یک‌باره نمی‌کند. [قرارداد فنی و نمونهٔ callback](../integrations/kits/README-fa.md).

## 💰 مبلغ و وضعیت‌ها

۲۰٬۰۰۰ تومان = ۲۰۰٬۰۰۰ ریال. `pay_amount` مبلغ نهایی فاکتور است و ممکن است کارمزد مشتری و افست داشته باشد؛ مبلغ را از callback مشتری نخوانید.

| وضعیت Store | اقدام فروشگاه |
|---|---|
| `paid` | پردازش ردیف تحویل ثبت‌شده با جلوگیری از تکرار |
| `sandbox_paid` | نتیجهٔ آزمایشی؛ بدون تحویل واقعی |
| `pending` / `unpaid` | هنوز مجوز تحویل ندارید؛ کال‌بک بعدی همان فاکتور قابل بررسی است |
| `reconcile` / `verifying` باقی‌مانده | تطبیق سابقه؛ تحویل یا درخواست پرداخت دوباره نکنید |
| `unknown` | شناسه در دیتابیس محلی نیست؛ تحویل ندهید |

HTTP 409 به‌تنهایی مجوز تحویل نیست؛ پاسخ آن مبلغ تأییدشده ندارد. خطای ارتباط هم نباید با create یا verify بی‌قید تکرار شود.

## 🧾 رسید پس از انقضا

برای فاکتورهای واجد شرایط، ثبت رسید و تصمیم فروشنده تا **یک ساعت پس از انقضای اصلی** ممکن است. این مهلت، اجازهٔ پرداخت جدید یا تمدید فاکتور نیست. رسید همان فاکتور بررسی می‌شود و تأیید دستی باید پس از مشاهدهٔ واریز واقعی باشد. [جزئیات رسید دیرهنگام](./LATE-RECEIPTS.md).
