# 🧾 انتقال کارمزد به مشتری — راهنمای پیاده‌سازی برای پلتفرم‌های ربات

این راهنما برای **توسعه‌دهندگان پلتفرم‌های ربات/پنل** است (Mirzabot، Seamless، Zitac و هر پلتفرم دیگری که CubePay را به کاربرانش ارائه می‌دهد): چطور به فروشنده اجازه بدهید کارمزد درگاه را — کامل یا بخشی — به دوش مشتریِ نهایی بیندازد، **بدون هیچ تغییری سمت CubePay**.

فایل‌های آماده‌ی [Foxima](./faoxima-ready-files/) همین الگو را پیاده کرده‌اند و می‌توانید به‌عنوان نمونه‌ی مرجع نگاهشان کنید.

---

## 🧠 ایده در یک خط

یک تنظیم عددی در پنل ادمین ربات + یک کلید روشن/خاموش. عدد این‌طور تفسیر می‌شود:

| عدد واردشده | معنی | مثال |
|---|---|---|
| `0` تا `100` | **درصد** اضافه‌شونده روی فاکتور (اعشار مجاز) | `9.9` → فاکتور ۱۰۰٬۰۰۰ تومانی می‌شود ۱۰۹٬۹۰۰ |
| بالای `100` | مبلغ **ثابت به تومان** | `5000` → فاکتور ۱۰۰٬۰۰۰ تومانی می‌شود ۱۰۵٬۰۰۰ |

این قانون در عمل ابهام ندارد: هیچ‌کس کارمزد ثابتِ زیر ۱۰۰ تومان نمی‌گذارد و هیچ‌کس درصدِ بالای ۱۰۰ نمی‌خواهد.

## ⚙️ کجا اعمال شود؟

**فقط موقع ساخت سفارش** — قبل از فراخوانی `POST /pay/create-order.php`، مبلغ را بزرگ کنید و همان را در `price_amount` بفرستید:

```php
/** مبلغی که مشتری باید بپردازد (تومان). $price = قیمت پایه‌ی سفارش. */
function cubepay_payable_amount(int $price, bool $feeEnabled, float $feeSetting): int
{
    if (!$feeEnabled || $feeSetting <= 0) {
        return $price;
    }
    return $feeSetting <= 100
        ? (int) ceil($price * (1 + $feeSetting / 100)) // درصدی — رُند به بالا
        : $price + (int) round($feeSetting);            // ثابت به تومان
}
```

## ✅ سه قانونی که نباید بشکند

1. **شارژ کیف‌پول/تحویل سرویس با قیمتِ پایه انجام شود، نه مبلغ فاکتور.** مبلغ اضافه فقط جبران کارمزد است؛ اگر با مبلغ فاکتور شارژ کنید، مشتری بیشتر از قیمت واقعی اعتبار می‌گیرد.
2. **اعتبارسنجی کال‌بک هیچ تغییری نمی‌خواهد.** امضای `sig` روی همان مبلغی ساخته می‌شود که درگاه گرفته (فاکتور بزرگ‌شده) و مثل قبل معتبر است. فقط مبلغ کال‌بک را با قیمت پایه‌ی خودتان *برابر* فرض نکنید.
3. **بعد از ذخیره‌ی تنظیم، تفسیرش را با یک مثال عددی به ادمین برگردانید** («۹.۹ → فاکتور ۱۰۰٬۰۰۰ تومانی می‌شود ۱۰۹٬۹۰۰ تومان») تا اگر منظورش چیز دیگری بود همان لحظه بفهمد.

## 💡 نکته‌ی ریاضی برای انتقال «کامل» کارمزد درصدی

کارمزد درصدی CubePay از مبلغ **ناخالص** فاکتور کم می‌شود. پس برای انتقال کامل کارمزدِ P٪ به مشتری، عدد تنظیم باید `P ÷ (100 − P) × 100` باشد، نه خود P:

| کارمزد درگاه | عدد تنظیم برای انتقال کامل |
|---|---|
| ۹٪ (CubePay VIP — [تعرفه‌ی لحظه‌ای](https://cubevps.ir/fees.php)) | **۹.۹** |
| ۳٪ (کریپتو) | **۳.۱** |

این نکته را در متنِ راهنمای تنظیم به ادمین نشان دهید — در فایل‌های Foxima همین کار شده.

## 🚀 چرا این الگو و نه تنظیم سمت درگاه؟

چون مبلغ فاکتور همیشه همانی می‌ماند که کد شما فرستاده — هیچ عدد «جادویی» از سمت درگاه تغییر نمی‌کند، کد اعتبارسنجی و شارژ فعلی‌تان دست نمی‌خورد، و همین یک پیاده‌سازی برای **کارت‌به‌کارت، کریپتو و VIP** یکسان کار می‌کند.
